## 实例三 · 反绕过机械校验（三层一致性守卫）

> 本章回答"渐进式加载怎么防三层漂移"——用机械校验兜底，不依赖 AI 记性。注：「读取时该读没读」已由姊妹文件 `三层加载机制.md` 的预注入硬墙治理（非本守卫职责，若你的平台支持 UserPromptSubmit 类钩子）。

### 1. 守卫是什么

**职责**：校验三层（摘要版/铁律版/详解存档）的一致性 + 多端布线巡检：
- ① **版本号一致**：三层 `version:` 字段必须相同（版本号铁律：改一层→三层一起升）
- ② **铁律上界一致**：三层标注的"铁律最大编号"必须相同
- ③ **布线巡检**：各端调度层（MEMORY.md / AGENTS.md 等）的触发句布线均须正确指向铁律版「加载时机」索引

**强制程度**：建议默认 `warn-only`（exit 0 仅告警）；`--strict` 才 exit 1（避免升版中途误拦）。

### 2. 挂载：钩子挂载模式（模板）

> 关键事实：守卫最好挂载在对话结束钩子（如 Stop 钩子），每次对话结束自动跑校验，三层若有漂移即输出告警。

```json
"command": "python3 {{你的守卫脚本路径}} --deliver"
```

即：每次对话结束自动跑守卫，三层若有版本/铁律上界漂移即输出告警。这是"渐进式加载"从软纪律升级为硬门禁的关键——它治"三层漂移"；「读取时该读没读」由预注入钩子治理（回答前即注入命中铁律段，无需拦截 Read 调用）。守卫另含触发规格覆盖校验，防触发规格与铁律版索引表脱钩。

**多端适配**：若你在多个端使用，守卫应扩展为各端调度层布线巡检（新增各端路径常量），对每端的触发句布线做同款校验——补上无 pre-response 钩子端的机械兜底。

### 3. 实测模板

```
$ python3 {{你的守卫脚本}} < /dev/null
✅ 三层一致：摘要版 v{{X}} / 铁律版 v{{X}} / 详解存档 v{{X}}
✅ 铁律上界一致：{{N}} / {{N}} / {{N}}
✅ 布线巡检：各端调度层 触发句→铁律版加载时机索引 布线正确
✅ 触发规格覆盖：{{N}} 条（yaml == 索引表 + anchor 存在）
exit 0（零漂移）
```

### 4. 与设计哲学的闭环

```
铁律修改（任一层）
  └─ 三层同步升版本号（版本号铁律·01 §六）
       └─ 对话结束钩子自动跑守卫
            ├─ 一致 → exit 0（无感）
            └─ 漂移 → 告警（人工介入补升版本）
```

这与 `00-宪法愿景.md §四 进化宪法（防漂移闭环）` 完全对应：规则变→升版本→记 ADR→钩子校验→不一致告警。

### 5. 待决项（非阻断·模板）

|---|---|---|
