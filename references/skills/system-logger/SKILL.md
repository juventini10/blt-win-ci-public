# 📝 系统日志 — 统一系统日志写入 Skill

> **设计哲学**：多端统一系统日志写入（实质性任务后自动触发，支持月度蒸馏）；由 **Stop 链末位校验守卫 `systemlog_stophook_check.py`** 机械兜底收口（今日个人AI档案有实质改动/提交却无系统日志→显形⚠️提醒·exit 0 不阻断·纯聊天日静默——非盲目强制写、避免噪声/空条目违背 Goodhart 防御），并由 **路由引擎 `route_unknown_unknown.py` 硬匹配触发** + **`app-config.json §3 闭环④`** 列为收口纪律，三层 enforcing 共同保证"做了工作必记日志"不靠自觉；历史变更见 `references/CHANGELOG.md`

## ⚠️ 铁律声明

**✅DO — 本Skill有两条执行路径：日写入 和 月度蒸馏。触发后第一条回复 ✅DO 运行 `render_mode_banner.py --mode {日写入|月度蒸馏}` 并逐字 relay 其 stdout 作为第一段（横幅由脚本产出，AI 接触不到构造权·防误·设计消除错误）。** ⛔DO NOT 自行编写横幅文本——自创格式=越权·违反铁律007反绕过。两模式数据源与执行逻辑完全不同，路径声明不可省。

**✅DO — 任务完成≠日志完成。任何实质性任务完成后 ✅DO 执行日志写入。** 日志范围只记录实际执行的任务，⛔DO NOT 编造任务内容——原因是编造日志比不写日志更糟。

**指令质量要求详见 `指令编写规范.md`。**

### "实质性任务"判定标准

> "实质性任务"✅DO按以下标准判定——不是所有操作都算实质性任务。

| ✅ 算实质性任务 | ❌ 不算实质性任务 |
|:--------------|:----------------|
| 文件变更（新建/修改/删除文件） | 改typo/修格式 |
| 记忆层更新（L1-L5写入） | 纯读取文件 |
| 版本发布（Skill/系统升级） | 查看文件内容 |
| Skill开发/修改 | 回答知识性问题 |
| 架构设计/规范编写 | 纯闲聊 |
| 认知发现/沉淀写入 | 单次命令执行（如ls/date） |

**判定规则**：产生了持久化产出物（文件/记忆层/版本）→实质性；未产生持久化产出物→非实质性。

## 🛡️ Poka-Yoke防误层（S级）

> 四道物理级防错，每道独立阻断。防误层是设计端约束——不依赖AI自觉，靠物理接触/步序强制阻断错误路径。

| 防误机制 | Poka-Yoke方法 | 防什么错 | 强度 |
|:---------|:-------------|:---------|:-----|
| date命令物理验证 | 接触法 | AI记错日期 | 最强（物理锚点） |
| **写入前Read确认+Section计数校验** | **接触法** | **Write覆盖已有内容** | **最强（写入前先Read+数section=物理阻断）** |
| Read回验 | 步序法 | 写入失败未发现 | 最强（空=阻断） |
| 日志格式Schema | 接触法+定值法（8字段固定数+扩展位（v3.16.0 声明对齐：`- **seal**：<8位hash>` 为 append_log_entry 机械追加的第9扩展字段（追加于条目体之后·⛔不计入 ≥8 字段门槛——门槛统计条目体八字段·v3.16.0批3 r2-C5 措辞改准）·⛔手写 seal 值无效——验签在 --verify-reply）） | 格式漂移 | 最强（格式不符=拒绝） |

> 四道防误的机制/阻断条件/对应步骤已内嵌各工作流步骤（date→步骤1、写入前Read+Section计数→步骤2.5、Read回验→步骤4、格式Schema→步骤3+4.2），此处仅留概览表，详述见对应步骤（v3.10.0 去重）

### 步序式防错（Motion-Step Method）

步骤强依赖：步骤1 date 实取 → 步骤2.5 写入前 Read 全文+Section 计数 → 步骤4 写入后 Read 回验——前步产出物缺失=后步物理阻断，不可跳过。
阻断条件：目标文件未 Read 全文=禁止 Write（防 TE-20260702 覆盖）；回读为空=报错重写。
验证：gate 负例实测可复现；Write 前无 Read 证据=阻断成立（AI 编不出 Read 记录）。

| 防误机制 | 锚点/执行位/可验证性 |
|:---|:---|
| date 命令物理验证 | 锚点=Bash date stdout；执行位=步骤1；验证=时间戳 vs 当日 date |
| 写入前 Read+Section 计数 | 锚点=实读+section 数；执行位=步骤2.5；验证=计数不符即阻断（实测） |
| Read 回验 | 锚点=重读非空；执行位=步骤4；验证=空即阻断（回读实测） |
| 格式 Schema 定值 | 锚点=8 字段固定数；执行位=步骤3+4.2；验证=gate 负例 7 组全命中 |

## 🔒 并发写入防护声明（2026-08-10 复审补·#069 转化）

cat >> 依赖 POSIX O_APPEND 原子性，并发追加不互相覆盖；检测靠门禁第四条+写后 grep -c 回验。⛔DO NOT 宣称"并发安全"，宣称"并发可检测"（极端同秒双写中间态靠回验发现）。 Alternatives：初版未用跨平台 flock（Windows 无原生语义）以 O_APPEND+回验为成本最优；v3.17.7 起 Mac 端补 `scripts/systemlog_lock.py` fcntl 独占锁（共享写锁·并发吞没根治），Windows 端仍走 O_APPEND+回验口径。

## 禁止行为

| # | 禁止 | 原因 |
|---|------|------|
| 1 | 编造时间戳/任务内容 | 时间或内容不真实=日志失去追溯价值且污染数据源 |
| 2 | 跳过三层校验直接输出验证块 | 校验没跑=验证块是空的——自欺欺人 |
| 3 | 不输出验证块 | 不输出验证块=未写入——这是系统日志Skill的铁律 |
| 4 | 对已存在的日志文件未先Read全文就直接Write | Write是全量覆盖——不先Read=原有内容丢失。来源：TE-20260702-001 |
| 5 | 独立追加计数器文件（已废弃·v3.6.0） | 派生数据独立写入=双本账漂移结构回归。来源：TE-20260716-001 |
| 6 | 手写字面时间戳（绕过 `append_log_entry.py`） | 时间值=AI 概率路径产物必漂（2026-08 日志第442行处实锤 20:46 vs mtime 14:35）；脚本内 `date` 是唯一真源，字面时间=物理锚点被绕过 |

## 📋 日志格式规范（强制执行）

**任何工具写入系统日志时，遵循以下格式。** 格式不一致 = 日志不合格。

### 文件骨架（新建当日日志时）

**骨架归脚本（铁律-017 已裁）**：新建当日文件由 `append_log_entry.py` 建文件分支生成（`# 系统日志 {YYYY-MM-DD}` + `## 今日概览` 三列表头 + `## {规范名}` 组头）——AI 不手写骨架，手写=绕过物理锚。消费者要点：概览头不含 📋（与门禁 `^## 今日概览` pattern 及 references/eval-set.md 预期一致·v3.10.1 格式单一真源）。

### 单条任务记录格式（v3.2精简版·对齐WorkBuddy实际格式）

```markdown
## {规范名}（裸结构锚点·⛔DO NOT 加 emoji/⚡/括号/时间/描述·详见「工具名规范」）

### [任务标题]
- **工具**：{{规范名，取自下方「工具名规范」节 allowlist；⛔DO NOT 用 identity 原始值直落盘}}
- **完成**：[时间 HH:MM | 取自last-reply产出签名时间]
- **类型**：[创建/修改/分析/同步/覆盖/写入/学习]
- **涉及文件**：[列出完整绝对路径]
- **对话摘要**：[用户意图+AI判断+关键决策，1-3句话概括对话核心过程]
- **结论**：[做了什么，结果是什么]
- **来源**：[🟢验证/🟡推断/🔴待验证]
- **置信度**：[🟢A/🟡B/⚠️C/🔴D]
```
