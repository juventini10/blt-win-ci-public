## 收口 enforcing 三层（叙述全文·原址=触发条件节内）

> **收口 enforcing 三层（2026-08-31 补登·印证"改动闭环律"需机械兜底）**：
> 1. **路由引擎 `route_unknown_unknown.py` 硬匹配**——会话中"系统日志/写日志/记日志"等触发词命中本 Skill，不靠 AI 自觉识别（settings.json Stop 链挂载，line 93）。
> 2. **`app-config.json §3 闭环④`**——将"实质性任务记系统日志收口"列为系统级收口纪律，SSOT 同步层必过。
> 3. **Stop 链末位校验守卫 `systemlog_stophook_check.py`**——会话结束前机械核验：今日个人AI档案有实质改动/提交却无系统日志→显形⚠️提醒（exit 0 不阻断·纯聊天日静默）。根治"做了工作却漏记"缺口，且非盲目强制写（避免噪声/空条目违背 Goodhart 防御）；本守卫本身已在守卫编写规范 §四 注册表登记（登记三件套件③）。
> 4. **写时守护自愈（`systemlog_watch.sh` 塌缩熔断→自动恢复·2026-08-31 补·根治跨端碰撞）**——检测到条目骤降>30% 的整文件覆盖（其他 AI 端并发整文件写回·`O_APPEND` 只防追加并发防不住整文件重写）时，不再隔离等人工，直接从 git HEAD（watch 每次合规写入即单文件 commit·HEAD 永远是最后好版本）恢复好版本+冲突方内容存证 `.collided-*` 侧车+追加恢复说明并固化入 git·全程不靠人记得——落实愿景①「机制自动运转·不依赖人记得」。
>
> **外部环境依赖声明（2026-09-01 Loop评估#9补·发布可移植性）**：以上第1-3层引用的 `route_unknown_unknown.py` / `systemlog_stophook_check.py` / `app-config.json §3` 及 `changelog_guard`、`git_commit_safe.sh` 均为**宿主环境可选依赖**，不随本 Skill 包分发——缺省时对应保障层静默降级（changelog_guard 有显式 N/A 终态，其余层为文本承诺不阻断日志写入主流程）；本 Skill 的**核心机械层**（门禁五查/归一/两步法/概览派生/自修复引擎）全部自包含于 `scripts/`，无外部依赖。

## 📋 Alternatives Considered（2026-08-10 复审补）

| 设计决策 | 选择 vs 替代 | 为什么不选替代 |
|:---|:---|:---|
| 日记载体 | Markdown 单文件 vs 数据库 | 每日高频追加+多端软链同步；数据库依赖外部服务 |
| 时间确定性 | date 命令实取 vs AI 凭印象 | TE-20260716 编造时间戳实测——确定性不走概率路径 |
| 写入姿势 | cat >> 追加+Read 前置 vs Write 覆盖 | TE-20260702 覆盖实测——追加+Read 物理防覆盖 |
| 门禁校验 | gate 脚本退出码 vs 纯文本清单 | 文本层可被跳过（2026-07-26 同源）——脚本阻断是物理约束 |
| 工具名规范 | allowlist 归一断言 vs AI 自觉 | 59 变体漂移实测（8/9）——机械闸门语义归 AI |
| 月度蒸馏存储 | 独立文件 vs 混存于日常日志 | 混存导致执行日日志膨胀（完整综览块占数十行）、月度蒸馏查阅困难（需在日常日志里翻）；独立文件分类清晰、查阅方便、不污染日常日志，执行日日志只存摘要+链接（v3.14.0·2026-09-02） |

## 功能定位

**不是"回顾器"**，是**"实时记录器"**。

本 Skill 做 **四件事**：
1. **记真实**：做了什么/改了哪些文件/结论是什么 2. **时间准确**：`date` 命令获取 3. **统一格式**：多端同一 Schema 4. **自验证**：写入后自动校验+验证外显块

## 技术实现

`date` → 读写日志 → 按格式写入 → 三层校验 → 验证外显；机械断言由脚本承担：门禁五查 `systemlog_gate_check.py` + 工具名校验 `normalize_tool.py`（含重复组检测）+ 概览派生 `reconcile_overview.py`（计数不变式机械保证）。
