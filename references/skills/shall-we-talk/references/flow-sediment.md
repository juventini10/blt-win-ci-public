## 主动沉淀

### Step 4:主动沉淀(六道锁 · 锁二点五为子检查点)

🔴 **宪法级 - Step 3→Step 4 之间的六道锁缺一不可。漏锁=沉淀未完成=对话无效。**
(锁序:锁一→锁二→锁二点五[子检查点]→锁三→锁四→锁五→锁六)

📦 **产出物**:提炼结果(≥1条发现)+ 写入位置标注 + 系统日志条目
🔌 熔断器
├─ 成功条件：六道锁全部通过 + ≥1条发现写入五层 + 确认签名归属
├─ 失败处理：重试
└─ 降级方案：标注"⚠️沉淀未完成"并回溯补齐

#### 锁一:产出检查锁(对话产出确认)
```
- [ ] 每问声明四行齐全(认知边界+思维路由+哲学判定+深度定位)- 所有已出口的问均声明完整(轮数本身为下限保险刻度,非达标证·见C3)
- [ ] 每问标注格式 `[维度N][Lx-工具名][哲学-视角名][深度X/4]` 完整
- [ ] 认知边界行引用了用户原话(不可凭空生成)
- [记录·非硬门] 深度覆盖刻度:本次实际覆盖层___(C3已降为描述性刻度,⛔不作达标硬门--硬门是收获门;如跳层已在声明中说明原因)
- [ ] 即时标记数量 ≥ 1条
- [ ] 如触及哲学信号,标注了 [哲学-视角名]
❌ 任一不通过 → 回到 Step 3 补声明
```

#### 🌀 盲区轴 T5 路由（意识到的盲区 · 悬置区）

> ⚠️ **术语区分（防 T5 歧义）**：本段是「盲区轴 T5 信号 = 意识到的盲区（悬置区五类触发之一）」，**不是**本 Skill 的「T5 对抗性测试声明」（OWASP 防御维度，见下方 T5 防御段）。两者同名不同义——本段只路由"用户明说不知道、且当场无法归因"的信号到悬置区。

**触发**：追问中用户说出"我不懂 X / 说不清这是什么 / 这里有个我现在不知道的东西"，且本轮对话无法给出根因解释 → 即 T5（意识到的盲区）。

**路由（自包含 · 规则 A）**：
- ✅DO：写入 `[记忆共享中心]/未知未知/悬置区.md` 前，先确认该文件存在；不存在则先用 Write 以 `references/unknown-unknown-headers.md` 的「悬置区模板」创建（含正确表头），再按 §1.6 schema 自下往上追加。
- ✅DO：条目格式 `### 残差#{序号} · {YYYY-MM-DD}` + 触发(T5)/归属(用户盲区|AI盲区|双方共盲)/来源(对话)/记录者(用户|AI)/状态(悬置未闭合)/毛坯描述(仅现象，不归因)。
- ⛔DO NOT：直接 Write 到不存在的文件 —— 原因是父目录/文件缺失会导致写入失败、盲区信号丢失。
- ⛔DO NOT：在写入时深加工/归因 —— 归因留到月报显形回看（悬置区.md §1.3 边界）。
- 📎 承接：月报第1.6步（daily-buddy）回看显形，本 Skill 不负责显形闭环。

```

- [ ] 路径映射判定:钩子触及"我可能成为谁/平行方向"→人生版本/;触及"这是不可改变的"→已接受边界/;触及"我想试个新方法"→原型试验/;认知陷阱→认知发现/;未闭环规避→回避模式/
- [ ] 盲区轴 T5 信号分支(意识到的盲区·区别于本 Skill T5 对抗性测试声明):用户明说"我不懂/说不清这是什么/这里有个我现在不知道的东西"且当场无法归因→路由 悬置区.md(未知未知·盲区轴),不落 认知发现/(已归因才落);触发即走上方「🌀 盲区轴 T5 路由」段
```

#### 🟡 锁二点五:反馈门禁(发现反馈段 · 结论块分离 · E2签名造假防护·定值法)

> 🔴 **设计端机制（规范§2.2 结论块分离 / E2定值法）**：对话发散，但交付结论收敛。本反馈段「核心发现 + 五层归属」即本轮**结论块**——与追问过程（推理链）物理分离，是锁五签名锁校验的收敛出口（锁五比对的是实际记忆写入，结论块与其同源单一出口，⛔DO NOT另起一份平行"结论"）。原因是结论不分离=签名可锚定任意对话片段造假。
```
- [ ] 核心发现(1-2句短语,✅DO基于本次对话具体信号)
- [ ] 五层归属标注
- [ ] "下次留意"写了吗
- [ ] 能量标注:本次对话揭示的是「耗能项 / 充能项」(接 最伟大的我/自画像/能量地图 段;钩子无能量信号→标注"本次无显著能量信号")
❌ 未完成 → 先写反馈段,不写完不进沉淀操作
⛔DO NOT -- 不以沉淀文件替代此段。沉淀写给系统,反馈段写给用户。
```

```

```

#### 锁六:终身记忆反哺锁(对话反哺速查表)

```

(完整规则与映射表 → 见下方【第三层】锁六)

反哺操作:追加一条到对应速查表的末尾(保持原格式),并标注「反哺来源:YYYY-MM-DD对话」

```

## 奥德赛生成

### Step 4.5:奥德赛生成(前向生成·v0.8.2新增·默认不跑)

> 🔴 **设计目的**:3 新目录(人生版本/已接受边界/原型试验)的**写入时机**。默认不跑以保诊断锋利;仅当用户显式请求才生成平行版本。
> **⚠️ 默认关闭**:Step 4 沉淀完成后,若无显式请求→直接进入锁六→输出报告。不主动提议、不默认生成。

**触发条件（满足任一才跑）**：
- 用户显式说："帮我设计几个方向" / "给我几个平行版本" / "如果换条路会怎样" / "生成人生版本"
- 重力判定触发且用户接住重新定向→可在对话末提示"要不要我生成几个平行方向"，用户说"要"才跑

> 📎 **完整规则**（执行流程/产出物/校验防空跑）→ Read `references/奥德赛生成.md`（触发：用户显式请求平行版本时）

**执行(触发后)**:
```
Step 4.5 奥德赛生成:
├─ 生成 3 个平行五年版本(Odyssey Plan),每个含:核心方向 / 若走此路的关键动作 / 可能得到的结果 / 信心指数(1-10)
├─ 写入 最伟大的我/人生版本/{YYYY-MM}-主题.md(按 _模板.md 格式)
├─ 若对话揭示不可变约束→同步写入 最伟大的我/已接受边界/{YYYY-MM}-主题.md
└─ 若用户想小步验证某个方向→写入 最伟大的我/原型试验/{YYYY-MM}-主题.md
```

**产出物(缺一不可)**:
- 📦 `最伟大的我/人生版本/{YYYY-MM}-主题.md`(≥3 个平行版本,格式合规)
- (条件)`已接受边界/` 或 `原型试验/` 文件(若触发对应分支)

**校验(防空跑)**:
- 未触发→确认跳过,报告中标注"Step 4.5 未触发(默认关闭),未生成人生版本"
- 触发→锁四完整性锁增项:人生版本文件存在且含≥3版本 / 写入位置已标注 / 系统日志已记
- ⛔DO NOT 把奥德赛生成当作每次对话的默认产出--它是显式触发的可选能力
